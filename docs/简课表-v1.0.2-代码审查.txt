公开分发前优先处理

1. [P1，可用性] 分享链接在预览前自动解压，缺少资源上限
   src/js/app.js:2139，src/js/transfer.js:57，src/js/importers.js:535
   页面打开分享链接后先解码，解压结果一次性读入内存，再解析 JSON。确认弹窗出现时这部分工作已经完成。预览还会逐对检查课程冲突并生成明细。在内存有限的手机上，异常输入可能导致页面冻结或退出。生成端的长链接提示只管提示长度。
   修复建议：在接收端限制编码字符数、压缩输入大小和流式解压的累计输出字节，超限立即终止；进入预览前限制规则数、文本长度和冲突明细数。文件入口同样先检查文件大小。HTML 表格的行列跨度和扩展作息的节数也应在分配内存前按实际表格和产品上限校验，见 src/js/importers.js:313、645。

2. [P1，数据完整性，实测] 不同标签页会静默覆盖彼此的编辑
   src/js/storage.js:30，src/js/app.js:90、186
   两个标签页各自持有启动时的数据副本。A 修改学期名称并保存，B 随后只点「保存作息表」，持久化的学期名称便退回旧值。相同的全量写入也能覆盖新增课程。
   修复建议：为数据保存持久修订号，在串行写入或事务中核对预期修订号。发现过期草稿时保留用户输入并提示重新加载或合并。storage 事件可用于提前通知其他标签页。保存因空间或权限失败时，应保留编辑窗口并显示错误；导入弹窗目前在落盘前关闭，见 src/js/app.js:1466。

3. [P2，发布隐私，已核对文件] 教学样本会随 ZIP 分发
   src/js/sample-fixture.js:2，src/js/app.js:65
   发布包内置的 HTML 与本地 samples/raw-school-timetable.html 内容完全相同。该文件本身已替换学生姓名、学号和教师姓名，仍保留校名、完整排课、教室、教学班代码和四处教学班内部标识。忽略 samples/raw-* 不能移除已经嵌入 JS 的副本。此项涉及开发时自带的样本，与安装后个人导入的数据是两条路径。
   修复建议：公开版改用人工构造的演示课表；需要保真的回归样本保留在测试目录，保留解析所需的形状，替换无关标识和值。

4. [P2，发布可靠性] 按部署指南重新打包，旧用户可能持续运行旧代码
   src/sw.js:11、118，scripts/package-release.sh:14，docs/iphone-deploy-guide.md:15
   当前工作线程脚本和缓存名依赖手工改版本。打包脚本只压缩目录。仅修改页面、样式或业务 JS 后重新发布，浏览器可能始终看到相同的 sw.js，既没有新的 waiting worker，也继续从旧缓存加载页面。
   修复建议：在打包和 GitHub Pages 工作流中共用一个步骤，按发布资源内容生成版本和缓存清单。在同一测试站点先安装 A，再部署仅改一项业务资源的 B，验收已有安装收到更新，更新后离线可用。

课表正确性与导入

5. [P2，实测] 通用 HTML 在浏览器中读错换行
   src/js/importers.js:321，src/js/html-inert-dom.js:65，tests/import-ics.test.mjs:251
   对同一份测试 HTML，Node 后备解析器主动为 br 添加换行；浏览器读取单元格 textContent 时不产生这些换行。Edge 实际解析出的课名是「线性代数(1-2节)1-16周教一201刘老师」，教室和教师为空。正方专用适配器按字段取值，内置样本导入成功。
   修复建议：在只读树上按 br 和段落提取文本行，使用真实浏览器回归同一份样本，独立断言名称、教师和教室。

6. [P2，实测] 恢复跨天调课会留下两次上课
   src/js/engine.js:334、353，src/js/app.js:611
   把周一课程移到周二，再在周一点击「恢复本次」，周一恢复，周二补课仍在。课次引擎同时返回两日的课程，日历也会据此导出两项。两笔例外目前没有关联标识。
   修复建议：用同一个调课标识关联原日停课与目标日补课，恢复时按标识成对处理，保留同日其他独立补课。

7. [P2，实测] 导入预览与实际保存的结果不同
   src/js/importers.js:623、533、653，src/js/app.js:1436
   默认恢复完整 JSON 时，预览显示 1 项有效、1 项已去重，但保存直接采用 fullData，最终落盘 2 项。合并时，预览只比较本次导入的数据；与已有课程重叠的条目实测被报告为 0 个冲突。覆盖时取消勾选「同时恢复……调停课例外」，实测备份里的 2 条例外仍然写入。
   修复建议：随覆盖、合并和恢复选项构造最终候选数据，向用户展示这份数据及其增删变化，确认后直接提交同一份结果。若完整恢复有意忠实保留重复项，应在预览明确说明实际将保留的数量。

8. [P2，输入校验] JSON 和导入码在确认备份格式前执行宽松规整
   src/js/importers.js:432，src/js/transfer.js:139，src/js/model.js:340
   JSON 入口只检查 courses 是数组，实测将声明 schemaVersion 2 的数据当作 v1 接收。导入码入口更早规整，缺少有效结构的内容也可能变成可确认的空课表。界面的覆盖前快照只在原来已有课程或例外时建立，已有自定义作息或仅有实践课的用户可能没有撤回点，见 src/js/app.js:1458。
   修复建议：先统一验证原始输入的版本、必要字段和边界，再执行明确的迁移或规整；对将丢弃的内容给出明细。覆盖前保护完整的旧状态。

9. [P2，日历安全与兼容性] 外部时区未经验证即写入日历属性
   src/js/model.js:351，src/js/ics.js:84、124
   备份中的时区接受任意非空字符串，导出时直接拼入 DTSTART 和 DTEND 的 TZID 参数，内部换行可能破坏日历记录边界。导出器只为 Asia/Shanghai 生成 VTIMEZONE，其他合法时区也可能被日历客户端解释错误。
   修复建议：对设置和导入共用 IANA 时区校验，拒绝控制字符。导出时转换为真实 UTC 时刻，或为使用的每个 TZID 输出对应的 VTIMEZONE。标准依据见 RFC 5545 第 3.2.19 节：https://datatracker.ietf.org/doc/html/rfc5545#section-3.2.19 。

另外值得纳入回归的边界

• HTML 导入的网络隔离。src/js/html-inert-dom.js:242 使用原生 DOMParser，页面没有将原始节点插回界面，但 Node 测试走另一套实现，不能验证 Safari 中的资源加载行为。对「导入不发网络请求」的承诺，建议使用只解析文本、不加载子资源的实现，并在目标浏览器验收网络请求。这里没有观察到用户课表外传。
• 规则 ID。src/js/app.js:1968 按列表长度生成 r_N，删除中间规则再新增可能复用尚在使用的 ID。同日的两条规则随后可能被同一个停课操作同时命中。使用稳定的唯一 ID，并在导入时验证引用。
• 作息时间。src/js/app.js:1715 只检查 HH:MM 格式。结束时间早于开始时间、时段交叉都能保存，并影响倒计时和日历导出。录入和恢复两个入口应共同验证时间顺序。
• 同源副本。src/js/storage.js:7 使用固定存储键，src/sw.js:54 会删除同前缀的其他版本缓存。如果在同一域名不同路径部署测试版和正式版，普通浏览器中的课表或缓存可能相互影响。需要数据隔离时使用不同源；缓存名应包含应用作用域，避免误删。
• iPhone 验收。在实际 HTTPS 地址上添加到主屏幕，在独立窗口内导入 JSON 并编辑一节课。等离线就绪后退出，开飞行模式重新打开，核对课程、最新编辑和周视图。再用系统日历确认导出事件与提醒。这项验收须在目标设备执行。原设计中的 CSV 和 .ics 文件导入仍列为后续功能，目前实现了 .ics 导出。
