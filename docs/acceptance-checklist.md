# 上线验收走查清单（V1）

V1 完成开发后，以以下 **3 次完整真机走查** 作为核心交付验收标准。

---

## 测试环境准备

- **电脑端开发与单元测试**：
  - 单元测试：`node --test tests/*.test.mjs`
  - 本地服务：`python3 -m http.server 8080 --directory src`，访问 `http://localhost:8080`
- **手机端 HTTPS 离线验收（必须使用手机信任的 HTTPS 地址）**：
  - 推荐方式 A：推送 `src/` 到 **GitHub Pages** 或 **Cloudflare Pages**（自动签发受信任 HTTPS 证书）。
  - 推荐方式 B：内网测试时使用受手机信任的自签 CA（如 `mkcert` 并在 iPhone 安装信任描述文件）或 Cloudflare Tunnel 临时 HTTPS 链接。
  - 注意：`http://192.168.x.x:8080` 仅用于预览排版，不满足安全上下文要求，无法验收 Service Worker 与断网打开。

---

## 走查一：iPhone 主屏幕冷启动并断网查看

**目的**：验证安全上下文、独立存储提示、原子离线缓存与飞行模式冷启动。

1. 在 iPhone Safari 打开已部署的 **HTTPS** 地址。
2. 点击「分享 → 添加到主屏幕」，确认图标与名称为「简课表查看」。
3. 返回桌面，点击**主屏幕图标**进入独立窗口模式（不带 Safari 地址栏）。
4. 保持联网，观察界面顶部/状态栏明确出现 **「已可离线使用」** 提示。
5. 切回桌面，在应用切换器中上划彻底杀掉「简课表查看」进程。
6. 开启 iPhone **飞行模式**（关闭 Wi-Fi 与蜂窝数据）。
7. 重新点击主屏幕图标冷启动：
   - [ ] 页面正常秒开，无白屏或 Safari 断网报错页。
   - [ ] 「今日视图」与「周视图」切换正常，当前周次与日期显示准确。
   - [ ] 可离线编辑单次课程（如临时改教室）并保存，重启后修改仍保留。

---

## 走查二：导入含单双周与调课的真实课表

**目的**：验证隔离解析、统一预览管线、单双周与调停课在三处输出的一致性。

1. 使用脱敏后的真实学校课表样本执行导入。
2. 进入「导入预览」步骤：
   - [ ] 预览清晰列出「识别成功 / 重复 / 冲突 / 无法识别」四类明细，且所有内容均为纯文本渲染。
   - [ ] 确认导入后，原有数据已保存为上一版快照（可一键撤回）。
3. 核对单双周课程：
   - [ ] 在奇数周可见单周课，切换到偶数周该课消失且双周课出现。
4. 核对「仅此一次」与「整组课程」编辑：
   - [ ] 对某天一门课执行「仅此一次 → 停课」或「仅此一次 → 换教室」，该天即时更新，其他周次不受影响。
   - [ ] 新增一次临时补课（`add`），该日期的今日视图与周视图同步显示。
5. 核对 `.ics` 导出一致性：
   - [ ] 导出 `.ics` 文件，检查其中展开的 `VEVENT` 数量、起止时间、UID、单双周分布以及上述停课/换教室/补课变更，与今日/周视图完全一致。
   - [ ] （真机补充核对）在 iPhone 导入 `.ics` 确认日历事件与提醒路径符合预期。

## 走查三：电脑备份恢复到手机独立窗口

**目的**：验证 iOS 独立存储隔离下的跨端迁移顺畅度与隐私提示准确性。

1. 在电脑端完成课表导入、作息调整与学期起始周一配置。
2. 在「发送课表 / 导入副本」面板中，确认界面清晰标注：持有完整链接或导入码的人可解码课表，通过微信等渠道发送时会经过对应通信渠道。
3. 分别测试两种恢复路径到 **iPhone 主屏幕独立窗口 App** 内：
   - **路径 A（JSON 备份文件，主推）**：电脑导出 `.json` 备份 → 发送到手机存至「文件」→ 打开主屏幕 App → 选择 JSON 恢复 → 预览确认。
   - **路径 B（复制导入码）**：电脑点击「复制导入码」→ 发到微信文件传输助手 → 复制全文 → 打开主屏幕 App → 粘贴导入码 → 预览确认。
   - **路径 C（快捷链接）**：验证 `#schedule=JKB1:...` 在浏览器打开后可触发导入预览（并提示 iPhone 用户若要同步进主屏幕 App 请使用导入码或 JSON 文件）。
4. 验收项：
   - [ ] 课程、单双周规则、调停课例外、自定义作息时间、学期开学日全部完整恢复。
   - [ ] 恢复后断开网络冷启动主屏幕 App，恢复的课表数据完整留存。
